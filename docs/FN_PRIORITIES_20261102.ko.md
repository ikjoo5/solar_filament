# FN 감소를 중심으로 한 다음 단계

- 사용자 확인: 공개 제출 원본과 사각형2개 제거본의 표시된 public LB는 모두0.55다. 표시된 점수 상승은 확인되지 않았다.
- 모델 이름을 고정하지 않고 실제 FN 감소와 FP 증가를 함께 평가한다. DETR 타일 선택은 이번 검증에서 새 raw 후보를 만들지 못했고 FN220이 그대로였으므로 우선순위를 낮춘다.
- 아래는 **기존 자체 모델의 고정 validation91장**에 관한 진단이다. 정답을 알 수 없는 public LB0.55 테스트 예측의 오류 개수와 동일한 수치가 아니다.

## FN220개의 후보 상태

best84 full native base/TTA 후보, 저장된 ROI70/80 raw 후보, YOLO reference/weak 후보에서 각 정답에 대한 최대 mask IoU를 계산했다.

|상태|GT 개수|연구할 문제|
|---|---:|---|
|IoU>0.5인 후보가 이미 존재|106|올바른 후보를 최종 출력에 포함하는 선택·중복 해결|
|최대 IoU0.1~0.5|74|부분 마스크, 잘림, 분리·병합, 재분할|
|최대 IoU<0.1|40|다른 입력 해상도·전처리·후보 생성 방식으로 포괄 가능성 확인|

- 이106개는 GT를 보고 맞는 후보가 있는지 확인한 수다. 이미 복구한 성과가 아니며, FP 없이 이106개를 실제로 고를 수 있다는 보장도 아니다.
- 74개 중28개는 최대 IoU가0.4~0.5 구간이다. 위치에 대한 단서가 있어도 마스크가 정답 기준을 넘지 못하면 FN으로 남는다.
- 검사한 것은 내보낸 후보 캐시 범위다. 어떤 모델·모든 추론 뷰에도 후보가 전혀 없다는 의미는 아니다.
- 한 사진의 여러 주석자는 평가상 각각 포함되므로 개수는 주석자별 GT 인스턴스 기준이다.

## DETR/ROI를 제외해도 선택 문제가 남는다

- native 후보와 YOLO reference/weak만 사용해도 FN 중75개에 IoU>0.5 후보가 있다.
- 이75개는 native와YOLO 양쪽13개,native만53개,YOLO만9개다.
- 나머지145개 중84개는 부분 겹침(0.1~0.5),61개는 겹침이 약하다(<0.1).
- 따라서 다음 실험이 DETR에 의존할 필요는 없다. 기존 모델 후보의 선택 문제와 새 후보 생성 문제를 분리할 수 있다.

## 무작정 후보를 추가하지 않는 이유

- 이번 ROI70 결과에서 기존 마스크와 겹침이 약한 후보를 추가 대상으로 보면 정답14개와FP105개였다.
- 이번 best84 타일 선택에서 새로 최종 통과한 정답은 원래 raw 후보에도 있었다. 확률 평균0.9 문턱을 넘는지가 달라졌을 뿐이다.
- 이런 사례는 후보 선택을 개선할 여지가 있음을 보여 주지만, 전역 confidence 문턱을 낮추거나 모든 모델의 마스크를 합치는 규칙의 유효성을 입증하지 않는다.

## 실험 우선순위와 평가

1. **후보 선택:** 기존 raw 후보에서 정답 후보의 중복·탈락 원인을 분석한다. 모델별 점수만 섞는 방법과 이미 실패한 일반적인 재순위화는 반복하지 않는다. 실제 이미지 근거·후보 간 경쟁·다중 뷰 안정성을 추가로 검증할 필요가 있는지 기존 결과와 대조한다.
2. **부분 검출:** 후보 위치가 잡힌 경우에 한해 재분할이나 스케일 변경을 시험한다. detector의 종류보다 완성된 인스턴스 마스크가 IoU0.5를 넘는지 평가한다.
3. **후보 포괄률:** 겹침이 약한 경우에는 전처리·다중 해상도·다른 segmentation 모델을 비교한다. 모델/전처리 변경으로 새 후보가 생겼는지와 최종 FP 비용을 별도로 기록한다.
4. **일반화 확인:** 전처리·후처리 규칙은 사용할 수 있는 기존5-fold OOF 기록에서 확인한다. 재학습이 필요하면 기존 고정 train/validation 분할을 사용한다. 평가 GT에서 골라낸 구체적인 마스크를 운영 규칙이나 학습 라벨로 사용하지 않는다.

각 실험의 기록 항목은 **새로 복구한 GT, 잃은 GT, 추가/제거FP, 최종 PQ**, 그리고 입력 후보 포괄률이다. 후보 포괄률 상승만으로 최종 성능이 올랐다고 보고하지 않는다.

근거: `fn_triage/summary.json`, `fn_triage/near_miss_summary.json`, `fn_triage/baseline_FN220.csv`. 이 문서는 다음 실험의 우선순위를 정한 진단이며 새 학습이나 새로운 개선 PQ를 보고한 결과가 아니다.

## 기존5-fold 자료 재사용 확인

- 707사진·1,154주석자 그룹·8,199GT에 대한 raw YOLO, native rich, 최종 후보, 원래 fold 분할이 클라우드에 남아 있다. 새 GPU 추론 없이 캐시 기반 후처리 검증을 진행할 수 있다.
- 현재 유지한 OOF 설정 `C4_then_C2`는 PQ0.4367525, TP5,244·FP2,891·FN2,955다. 이 값은 새 결과나 리더보드 점수가 아니다.
- 앞서 언급한 'FN2,955개 중1,965개에 후보가 있다'는 **4개 geometric view** 범위였다. 전체 multiview와 최소 면적300px 조건에서는 FN2,306개에 IoU>0.5 후보가 있고649개에는 없다. 전체 GT 후보 존재율은7,544/8,199=92.01%다.
- 최소 면적 필터를 없애면 후보 존재율은93.01%지만, 후보 수·FP·상호 충돌이 많다. 이것은92~93% recall을 달성했다는 뜻이 아니다.
- native는5fold 모두30epoch,YOLO는30/30/30/30/25epoch이므로 완전히 동일한 학습량의 비교가 아니다. 이 OOF도 여러 번 사용한 개발 자료이며 새 독립 holdout은 아니다.
- 기존 native 복구, 일반적인 전역 재순위화·soft-NMS·합의 점수 선택, 고정 분할에서의102개 특징 기반 context 선택기는 이미 검증에서 좋은 결과를 내지 못했다. 이를 새 방법처럼 다시 제안하지 않는다. 자세한 결과는 `fn_triage/oof_readiness.json`에 기록한다.
- 따라서 후보가 전혀 없는 경우의 모델·전처리 실험과, 이미 있는 유효 후보가 탈락하는 경우의 선택·충돌 처리 실험을 따로 검증한다. 학습이 필요한 선택 모델은 사용자와 정한 기존 고정 분할을 사용한다.
