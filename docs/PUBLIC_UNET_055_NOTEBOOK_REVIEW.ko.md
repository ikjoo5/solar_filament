# 공개 Kaggle U-Net 0.55+ 노트북 검토

- 대상: https://www.kaggle.com/code/lamhuy8904/solar-filament-unet-segmentation-0-55
- 확인일: 2026-11-01
- 공개 API가 반환한 최신 버전: 35. 메타데이터의 마지막 실행: 2026-10-29.
- 페이지에 연결된 scriptVersionId 347030249 다운로드와 API 최신 소스의 8개 셀 내용이 모두 같다.
- 공개 노트북을 실행하지 않고 JSON·Python AST·저장 출력·내장 CSV 데이터를 분석했다. 추가 학습 실험은 진행하지 않았다.

## 결론

**이 공개 버전의 제출 CSV는 노트북 앞부분에서 학습한 U-Net으로 생성되지 않는다.** 코드에 압축해 넣은 기존 예측 CSV를 풀고, 테스트 파일명에 맞춰 해당 RLE를 복사한다. 따라서 제목과 주석의 `0.55+`를 공개된 U-Net 학습 코드의 재현 성능으로 해석할 수 없다.

0.55는 노트북 제목과 작성자 주석에서 확인한 주장이다. 이 검토에서 Kaggle 제출 점수를 독립 확인하지는 않았다. 내장 예측을 만든 원래 모델·학습 과정·데이터 출처는 이 버전에서 확인되지 않으며, 그 출처나 규정 준수 여부를 단정하지 않는다.

## 실제 코드 경로

|단계|공개 소스에서 확인한 동작|
|---|---|
|학습 데이터|COCO 이미지 레코드의 앞 60개를 선택한다. 주석자별 이미지 ID가 있으므로 60개 독립 원사진이라는 뜻은 아니다.|
|분할|목록 앞 15%를 validation, 나머지를 train으로 쓴다. 물리적 사진별 그룹 분할 검사는 없다.|
|모델|사전학습 없는 간단한 1채널 U-Net, BCE와 Dice를 각각 0.5 비중으로 사용한다.|
|학습|256 crop, batch 4, AdamW, 5epoch. Validation은 전체 이미지를 256으로 줄여 binary Dice를 계산한다. 공식 instance PQ가 아니다.|
|저장 출력|CPU 학습, 60개 레코드, validation Dice는 첫 epoch 약 0.0001, 이후 표시값 0.0000이다.|
|내장 예측|`CHAMPION_PAYLOAD`라는 문자열을 Base85 → LZMA → CSV 순으로 복원한다. 모델 가중치가 아닌 RLE 예측 데이터다.|
|테스트 처리|파일명으로 내장 RLE를 조회한다. 이미지 픽셀을 읽거나 모델을 호출하지 않는다.|
|없는 파일명|2048×2048 가운데 `[1000:1048, 1000:1048]` 영역의 48×48 사각형을 넣는다.|
|겹침 제거|`remove_instance_overlaps()`는 정의되어 있지만 호출되지 않는다. 해당 함수가 이 제출 점수를 높였다는 증거도 없다.|
|최종 제출|내장 예측과 사각형 fallback을 합쳐 `submission.csv`를 쓴다. 학습 checkpoint를 불러오지 않는다.|

`model(...)` 호출은 학습 배치와 validation 배치에서 각각 한 곳뿐이다. 학습된 모델의 출력·가중치는 최종 제출 데이터 흐름에 연결되어 있지 않다. 앞부분의 U-Net 학습을 변경해도 같은 내장 예측과 테스트 파일 목록을 사용하는 제출 결과는 바뀌지 않는다.

## 내장 데이터 직접 확인

문자열 상수를 AST에서 추출하고 제한된 크기로 압축을 해제해 CSV를 확인했다. 노트북의 함수를 호출하거나 임의 코드를 실행하지 않았다.

- 압축 해제 CSV: 388,929 bytes, `filament_id,segmentation_rle` 두 열.
- 예측 1,342개, 서로 다른 테스트 파일명 178개.
- 사용자가 제공한 공식 이름 목록과 대조하면 178개가 모두 대회 test에 있고 train에는 없다.
- 누락된 test 파일명은 `20160513133714Th`, `20180507140210Th`다. 두 장에 사각형을 넣으면 저장 출력과 같은 총 1,344행이 된다.
- CSV SHA256: `7e6570382c620ce402bb0048336a319cd1a590bb08facb66bec3729c622de7e4`.
- 공개 API 최신 notebook SHA256: `906841cbc0e1f50b89bda6648b1c7f85eff16975e62c3679a120141aa172a687`.

이 CSV를 우리 학습·검증·제출에 사용하지 않았다. 공식 test 이름과 일치한다는 사실은 데이터의 원래 생성 방법이나 점수의 진위를 입증하지 않는다.

## 우리 파이프라인에 대한 의미

- 우리 native 모델도 이미 ConvNeXt-Tiny encoder의 U-Net이다. 실제 제출은 YOLO와 native를 결합한 구성이다.
- 우리 native는 1024 crop, foreground/spine 출력, 타일 추론과 4방향 TTA를 사용한다. 이 공개 노트북의 단순 U-Net이 그 구성보다 우수하다고 비교할 근거는 없다.
- 현재 공개 버전에서는 0.55를 만든 학습·추론 절차가 빠져 있어, 우리 고정 validation에서 그 모델을 재현·비교할 수 없다. 필요한 것은 내장 예측을 생성한 원래 코드와 가중치다.
- 같은 내장 예측을 재사용한 참가자끼리 점수가 같아지는 현상은 설명할 수 있다. 리더보드의 20~100위 참가자가 실제로 모두 이 노트북을 사용했는지는 확인하지 않았다.
