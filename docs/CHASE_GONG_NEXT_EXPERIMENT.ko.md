# CHASE 형상 합성과 GONG 영상 적응: 다음 실험

상태: **실험 설계**. 아래 CHASE 형상 렌더러와 CHASE→GONG 변환기는 아직 구현·학습하지 않았다. 기존 코드에서 재사용할 부분과 새로 필요한 부분을 구분한다. SWEFFI는 사용자 요청대로 마지막 단계까지 보류한다.

## 우선 판단

현재 보유한 코드와 자료로는 **CHASE 마스크의 형태를 이용한 국소 GONG 합성부터 작은 파일럿으로 검증하는 편이 구현과 원인 분석에 유리하다.** GONG 배경과 기존 정답을 보존하면서 추가한 객체의 명암·크기·위치·라벨을 통제할 수 있고, 이미 검증한 copy-paste 도구의 상당 부분을 재사용할 수 있다.

전체 CHASE 영상의 GONG 적응도 유효한 비교 후보다. 실제 영상의 구조와 맥락을 보존한다는 장점이 있지만, 현재의 8비트 PNG만으로 GONG의 파장 응답·대기 흐림·보정 과정을 정확히 재현할 수는 없다. 합성 우선이라는 판단은 첫 구현 비용과 실험 통제에 관한 것이며, PQ 상승이나 최종 우월성이 확인됐다는 뜻은 아니다.

국소 합성의 또 다른 장점은 **선택한 CHASE 양성 형태만 추가할 수 있다는 것**이다. AHAS mask 밖의 모든 CHASE 픽셀을 확실한 배경으로 다시 학습시키는 의존성을 줄인다. 이것이 현재 하락의 유일한 원인이라고 확인된 것은 아니지만, 외부 자동 라벨의 누락과 촬영 배경 변화가 GONG 표현을 훼손할 위험을 분리해 시험할 수 있다. 기존 GONG 배경에도 미주석 객체가 있을 수 있으므로 합성 위치와 알려진 GT 보존 검사는 계속 필요하다.

| 기준 | CHASE 형상 → GONG 국소 합성 | 실제 CHASE → GONG 영상 적응 |
|---|---|---|
| 가져오는 정보 | 마스크·중심선·길이·굽음·가지 형태 | 실제 필라멘트의 구조·밝기·주변 맥락 |
| GONG 배경 | 실제 GONG train 영상 그대로 사용 | 전체 배경 밝기·텍스처·잡음 분포를 근사해야 함 |
| 새로 필요한 구현 | 형상에 GONG 명암을 입히는 렌더러 | 영상 통계 추정 및 제한된 관측 특성 변환기 |
| 기존 코드 재사용 | split 검사, 합성 삽입, 겹침 방지, 라벨 보존, 기록·재개 | CHASE 다운로드·무결성 검사, 이미지/마스크 정렬, Dataset |
| 주요 실패 위험 | 경계 자국·부자연스러운 질감·작은 조각을 과도하게 생성 | 영상이 비슷해져도 파장·라벨 기준 차이가 남음 |
| 라벨의 의미 | 직접 삽입한 합성 객체의 마스크 | AHAS의 기존 자동 binary 라벨 |
| 첫 역할 | 목표 촬영 조건에서 외부 형태의 추가 가치 확인 | 실제 외부 영상의 추가 가치와 영상 변환 효과 확인 |

## 현재 결과가 알려 주는 범위

고정 GONG validation 91개 관측/101개 주석 그룹/708개 GT를 독립 모델, 단일 base view, 동일 최소 디코더로 평가했다. 이 값들은 기존 전체 복합 파이프라인이나 public LB 점수가 아니다.

| 모델 | 원본 입력 PQ | limb 입력 PQ |
|---|---:|---:|
| 기존 YOLO | 0.399286 | 0.396637 |
| CHASE 60epoch YOLO | 0.077358 | 0.091471 |
| 기존 native U-Net | 0.400068 | 0.406802 |
| CHASE 60epoch native U-Net | 0.072098 | 0.066450 |

- CHASE만 60에폭 추가학습한 현재 방식은 GONG 성능을 유지하지 못했다. CHASE 자체가 무용하다는 실험은 아니다.
- 새 native의 원본 입력에서 foreground 임계값을 0.5→0.05로 낮춰도 PQ는 0.072098→0.084986이었다. 고정 반경3 팽창은 0.120052까지 올렸지만 FP도518→559로 늘었다.
- 새 YOLO 원본 입력에서 confidence0.2의 FP579개 중317개는 예측의90% 이상이 한 GT 내부에 있지만 그 GT의 절반 이하만 덮는 작은 조각이었다. GT와 전혀 겹치지 않는 FP도181개 있었다.
- 따라서 낮은 confidence나 limb on/off만으로 해결되는 문제가 아니며, 외부 데이터의 촬영 분포와 감독 신호를 함께 검토해야 한다.

## 합성은 무엇을 옮기는가

단순한 중심 좌표 `(x, y)`만으로는 필라멘트 모양을 표현할 수 없다. **마스크/윤곽과 필요한 경우 중심선**을 형태 재료로 사용한다. 원래 태양에서의 절대 좌표는 필수 정보가 아니다.

1. CHASE 원본과 binary mask의 좌표를 기존 정렬 코드로 일치시킨다. 원본 mask·이미지와 정렬 이력을 보존한다.
2. 합성 donor의 형태를 선택한다. AHAS 연결요소를 전문가가 구분한 실제 객체 ID라고 부르지 않는다. 관련 없는 조각을 자동으로 하나의 원래 필라멘트라고 묶지 않는다. 합성에 쓸 형태를 선택하는 과정과 외부 자료의 원래 라벨을 삭제하는 과정은 구분한다.
3. GONG **train**의 실제 필라멘트와 주변 배경에서 상대 명암, 폭, 가장자리 변화, 흐림 범위를 추정한다. CHASE 마스크를 일률적으로 검게 칠하거나 모든 모양에 동일한 대비를 주는 방식은 피한다.
4. 해당 형태 안에 GONG에 가까운 어두운 강도 변화를 만들고 실제 GONG train 배경에 삽입한다. 경계의 급격한 색 차이·직사각형 패치 흔적·투명한 라벨 영역을 검사한다. CHASE 영상의 상대 흡수 패턴을 재사용하는 방식과 형태만 사용하는 방식은 별도 변형으로 기록한다.
5. 기존 GONG 객체·정답을 유지한다. 모든 train 주석 그룹의 foreground 합집합과 여유 영역을 삽입 금지 영역으로 삼는다. 추가 객체끼리도 겹치지 않게 한다. 이는 알려진 주석과의 충돌을 막는 검사이며 미주석 객체가 전혀 없다는 보장은 아니다.
6. 추가한 객체의 mask를 합성 instance로 기록한다. 영상 변형과 mask 좌표는 함께 변경하고, 보이지 않는 객체를 라벨만 남기는 결과는 거부한다.

CHASE mask가 어두운 중심 조각만 포함한다면 그대로 복사하는 것만으로 대회의 넓은 객체 정의가 보충되지는 않는다. 폭·면적을 다루는 규칙은 GONG train의 분포에서 정하고 영상과 마스크에 일관되게 적용한다. **validation GT에 맞춰 donor를 팽창시키거나 분리·병합하지 않는다.**

첫 렌더러는 전체 태양 영상을 생성하는 모델이 필요 없다. 국소 명암·텍스처 합성과 보수적인 합성 품질 검사를 이용할 수 있다. 실제 GONG 관측과 같은 물리 영상이라는 주장은 하지 않는다.

## 영상 적응을 비교할 때

- 원반 정렬 이후 반지름별 배경 밝기와 국소 대비를 GONG train 통계에 맞춰 제한적으로 조절한다. 흑색 원반 바깥까지 포함한 단일 히스토그램을 무조건 맞추지 않는다.
- 흐림은 공간 해상도·원반 픽셀 척도를 맞춘 뒤 측정한다. 모든 CHASE 영상이 GONG보다 선명하다고 가정하고 일률적으로 흐리게 만들지 않는다.
- 실제 GONG과 비슷한 잡음·압축 범위를 사용할 수 있지만, 작은 필라멘트가 보이지 않을 만큼 변형된 경우의 라벨 가시성을 따로 점검한다.
- 단일 PNG에는 파장별 정보가 없다. CHASE spectral cube와 관측 응답함수가 있으면 GONG 필터 대역의 강도를 모사할 여지가 있으나, 현재 PNG 변환을 그 물리적 재현과 동일시하지 않는다.
- 같은 시각의 CHASE/GONG 관측 쌍을 확보하면 변환 검증과 라벨 등록에 더 직접적인 근거가 된다. 시간차·파장 응답·시선 방향·정렬 오차 때문에 등록한 라벨도 약한 감독 신호로 취급한다.

## 같은 예산의 순차 실험

모든 분기는 원래 GONG 학습 가중치에서 시작한다. CHASE-only 60epoch 가중치를 공통 출발점으로 쓰면 이미 발생한 성능 하락과 새 활용법의 효과가 섞인다.

| 실험 | 학습 자료 | 묻는 질문 |
|---|---|---|
| A | GONG train + 동일 예산의 GONG 증강 | 추가 업데이트 자체의 효과는 얼마인가? |
| B | GONG train + CHASE 형태의 GONG 합성 | 외부 형태를 목표 배경·명암에 넣는 것이 도움이 되는가? |
| C | GONG train + 정렬한 실제 CHASE | 실제 외부 영상의 보조 학습 효과는 얼마인가? |
| D | GONG train + GONG 특성으로 변환한 실제 CHASE | C 대비 영상 적응의 순수 효과는 얼마인가? |

- **먼저 A/B를 구현·비교**하고 합성 품질과 추가 가치를 확인한다. 실제 영상 적응은 C/D를 한 쌍으로 비교한다. 네 분기를 한꺼번에 장기 학습할 필요는 없다.
- 두 모델(YOLO와 native)에 적용할 수 있도록 데이터 계층을 설계한다. 어떤 모델에서 효과가 있는지는 각각의 독립 PQ와 최종 복합 파이프라인 PQ를 구분해 확인한다.
- 초기 가중치, GONG 노출 수, 전체 optimizer update 수, seed, 평가·체크포인트 선택 규칙을 기록한다. 추가 표본이 늘어서 업데이트가 많아진 차이를 외부 데이터의 효과로 해석하지 않는다.
- 에폭은 해당 실험의 지정 학습 목록 전체 순회로 정의한다. 고정 이미지 수의 일부만 돌린 구간을 전체 에폭이라고 부르지 않는다. 대조군은 같은 업데이트 예산을 GONG 증강으로 채운다.
- 첫 점검 구간의 점수로 완전 수렴했다고 주장하지 않는다. 학습 곡선과 GONG PQ/FP/FN이 유망한 조건만 같은 스케줄에서 연장한다. CHASE 자동 라벨 loss 감소만으로 채택하지 않는다.
- C와 D는 외부 라벨 가중치·선택·불확실성 처리를 동일하게 둔다. 이미지 변환 효과를 측정하면서 loss·BN 정책까지 동시에 바꾸지 않는다.
- AHAS는 binary 자동 라벨이므로 GONG의 수동 instance 라벨보다 약한 보조 감독으로 검토한다. 외부 binary foreground loss와 YOLO의 proxy instance 학습은 같은 문제로 취급하지 않는다. YOLO의 연결요소 단위와 작은 조각 편향을 별도 감사한다.
- 학습 방식/하이퍼파라미터 비교는 기존 고정 분할에서 한다. 채택 후보의 일반화 확인은 이후 정해진 5-fold 및 실제 제출 단계와 구분한다. 반복 사용하는 validation에서 고른 최고값을 독립 성능으로 보고하지 않는다.

## 누수와 재현 기록

- GONG 배경·텍스처·명암 통계·donor 규칙 산출에는 train만 사용한다. validation/test의 이미지·정답·공개 예측 RLE를 합성 재료나 목표 라벨로 사용하지 않는다.
- 실제 관측 파일명/촬영일·중복 이미지·주석자별 변형을 기준으로 원본을 추적한다. 같은 관측에서 파생된 합성·변환 자료는 원본과 같은 학습 역할에 둔다.
- CHASE 품질 평가용 분할을 만들면 원본 관측/시간 그룹으로 나누고, 이미 CHASE 전체로 학습한 가중치에 대해 새 독립 holdout이라고 주장하지 않는다.
- 각 합성 표본에는 GONG 배경 SHA, CHASE 이미지·mask SHA, 원본 ID, seed, 변환 행렬, 삽입 위치, 명암 파라미터, 전후 mask 면적, 삽입 실패 사유, 전체 설정/코드 버전을 남긴다.
- 대용량 이미지·라벨·학습 가중치·예측은 로컬/Drive에 둔다. GitHub에는 코드·설계·설정 예시·생성 규약을 보관한다.

## 기존 구현과 아직 필요한 구현

| 파일/API | 현재 하는 일 | 이번 설계에서의 사용 |

| `tools/targeted_synthetic_data.py`: `make_donor_patch` | 기존 GONG donor의 측정된 어두운 log residual 추출 | 합성 원리를 참고. CHASE shape-only 렌더러로 이미 구현된 것은 아님 |

| `tools/chase_independent_plain_worker.py` | 기존/CHASE 모델 × raw/limb 독립 추론, 검증 캐시 | 새 가중치/입력 계약에 맞춘 평가 어댑터 작성 시 참고 |

기존 targeted generator의 GONG donor ID 목록, 최소300px/최대5000px 같은 역사적 조건은 CHASE에 그대로 적합하다고 간주하지 않는다. `prepare_dataset`은 기존 v2/v3 자료를 위한 고정 입력 계약이므로 새 CHASE 자료를 이름만 바꿔 연결하지 않는다. **새 입력 manifest, 형상 렌더러, 혼합 dataset, 동일 예산 launcher 및 대응 검증이 필요하다.** 기존 평가·제출 코드는 보존하고 새 실험 namespace에서 개발한다.

## 근거

- [CHASE 임무 설명](https://doi.org/10.1007/s11433-022-1893-3), [GONG H-alpha 자료 설명](https://nso.edu/data/nisp-data/h-alpha/).
- 저장소의 [CHASE와 GONG 비교](CHASE_VS_GONG_20261104.ko.md)는 당시의 CHASE-only 사용자 설정을 기록한 역사 문서다. 현재의 GONG+CHASE 활용 설계는 이 문서를 따른다.
