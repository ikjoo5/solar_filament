# Public LB 0.55 예측을 자체 파이프라인 개선에 활용하는 계획

## 기준선과 목적

- **최신 사용자 리더보드 확인:** 자체 T4 baseline 0.39 / R1 0.39 / 공개216개 추가 0.42 / 독립적인102개 교체 0.45. 외부 원본은0.55다. 자체 모델과 혼합 CSV 기준선을 구분하며, 혼합 CSV 후속 실험의 비교 기준은0.45다.
- R1은 표시 public 점수에서 상승이 확인되지 않았다. 반복 평가한 OOF에서의 작은 이득 기록은 유지하되, 현재 test 누락 복구와 마스크 범위 교정 실험의 우선순위를 높인다. 표시 점수가 같다는 사실은 반올림 이전의 정확한 점수까지 같다는 뜻은 아니다.

- 사용자가 동일 대회 public leaderboard에서 확인한 점수는 공개 예측 0.55, 자체 YOLO+best84 제출 0.39다. 공개 예측은 전체 점수가 더 높은 유용한 교사 예측이다. 모든 개별 마스크가 우월하다는 뜻은 아니다.
- 자체 모델 실험의 기준선은 **자체 YOLO+best84**다. 외부 0.55 CSV 수정 실험과 자체 모델의 개선을 별도 기록한다.
- 현재 실행 중인 T4 전체 추론은 원본 이미지 → 기존 YOLO+best84 → R1 한 번 순서다. 이번 진단은 저장된 캐시를 읽으며 실행 중인 학습·추론 코드나 제출물을 바꾸지 않는다.
- 0.55 참조를 이용해 실험 가설을 만들고, 정답이 있는 고정 validation/5-fold OOF에서 PQ·TP·FP·FN을 측정한다. 공개 예측과의 일치도는 별도 지표로 기록한다.

## 확인된 단서

- **추가 제출 결과:** 기존0.39 마스크1,347개를 그대로 두고 공개 마스크216개를 추가한 파일의 실제 public LB가 **0.42**라고 사용자가 확인했다. 표시점수 +0.03이다. 이는 해당 추가 묶음의 public 평가 순효과가 양수라는 근거이며,216개 각각의 정답 여부는 알려주지 않는다.
- 225개를 모두 추가했던 파일은 겹침 때문에 제출 거절됐다. 실제 제출기에 맞춰 겹치는9개를 제외했으며, 수정본1,563개는 전체 겹침0이다.
- 기록을 구분한다: 자체 모델의 기존 제출0.39 / 공개216개를 추가한 혼합 제출0.42 / 공개 원본0.55. 실행 중인 자체 best84+R1 결과의 점수는 아직 제공되지 않았다.
- 기존 진단 셀은 그대로 사용한다. 결과가 오면 `public055_addition_to039_v2/priority_trace_targets216.json`의 공개 ID216개를 먼저 대조해 원시 후보 존재 여부·단계별 탈락을 분석한다.216개 전체를 정답 라벨로 바꾸지 않는다.

## 이후 실험의 고정 체크 항목

- 사용자 요청에 따라, 자체 모델 실험은 **정답이 있는 데이터의 PQ·TP·FP·FN**과 **고정216개 참조 예측의 복구 정도**를 함께 기록한다.
- 216개는0.42제출에 추가된 공개 마스크 ID로 고정한다. 후속 실험마다 유리한 대상으로 목록을 바꾸지 않는다. `configs/reference216.json`이 기준이다.
- 원시 후보와 최종 마스크를 따로 비교한다. 각 참조에 대해 최대 mask IoU를 구하고 **strict IoU >0.5 대응 개수/216**, 평균 최대IoU, 이전 실험 대비 새로 대응·대응 상실한 ID를 저장한다.
- 원시 후보에는 있지만 최종에 없는 대상은 선택/제거 진단으로, 원시 후보에도 없는 대상은 생성 단계 진단으로 분류한다. 알려지지 않은 원시 기록은 미측정으로 표시한다.
- 학습·validation만 실행하고 test추론을 하지 않은 실험의216지표는 **미측정**이다. 부분 test결과를216전체의 누락으로 집계하지 않는다.
- 자체 모델 출력과 공개 마스크를 복사한 혼합 출력은 별도 표로 기록한다.0.42혼합제출은216개를 넣었으므로 참조 대응률100%이며, 이것을 자체모델의 검출능력으로 기록하지 않는다.
- 기존 Colab 진단셀의 `reference_instances.csv` 또는 완성된 test제출CSV를 `tools/track_reference216.py`로 읽는다. 추적을 위한 추가GPU추론이나 새Colab셀은 필요하지 않다.

## 공개 예측에서 추가로 활용할 대상

- 공개 자연 마스크 1,342개는 **추가한 216 / 겹침으로 제외한 9 / 부분 대응 193 / IoU>0.5 대응 924**로 나뉜다. 부분 대응은 IoU 0.1~0.5다. 이것은 예측 간 대응 분류다.
- 부분 대응 193개 중 상호 최상위 대응은 159개이고, 서로 오직 한 상대 마스크와만 픽셀이 겹치는 독립적 1:1 대응은 102개다. 193개 중 45개는 기존 분리·병합 44그룹 중 31그룹에 속한다.
- 다음 CSV 실험은 **점수 0.42 혼합 제출에서 독립적인 102개만 공개 마스크로 교체**하는 것이다. 기존 ID·객체 수 1,563·고정 216 마스크를 유지하고 전체 겹침 0을 검사한다. 교체 묶음의 순효과를 0.42와 비교한다.
- 확인된 후보: `submission_hybrid042_replace102_no_overlap.csv`의 public LB는 **0.45**다. 관련 기록은 `artifacts/public055_replace102_v1/`에 저장한다.
- 제외했던 9개를 모두 넣으려고 기존 마스크를 깎는 방식은 기존 8개의 형상을 바꾸고, 한 마스크는 35.94%만 남는다. 이번 102 교체 실험에는 이 9개를 섞지 않았다.
- 정확한 기존 0.39 마스크 B와 참조 216개 T는 픽셀 겹침이 0이다. R1이 B의 픽셀을 보존하며 면적 a≤0.25|B|만 추가하면 `IoU(B∪A,T)≤a/(|B|+a)≤0.2`다. 따라서 이 기준선의 216개 복구에는 새 후보 추가·생성·큰 형상 교체가 필요하다. 새 T4 baseline은 재추론 차이가 있으므로 실제 기록으로 확인한다.

## 102개 교체의 결과와 자체 모델 개선 가설

- 마스크 수1,563개와 고정216개를 유지하고102개의 형상만 교체해 **0.42→0.45**가 확인됐다. 기존 마스크 범위를 수정하는 방향에도 실제 public 평가상 순이득이 있었다.
- 공개 마스크가 더 큰 경우70개, 작은 경우32개다. 면적이 기존의2배를 넘는 경우53개, 절반 미만인 경우15개다. 일괄적인 약한 팽창만으로는 이 차이를 설명할 수 없다.
- 이전0.39 마스크의 픽셀을 모두 유지하고 면적을최대25%만 늘리는 R1 제약에서는, 픽셀을 최적으로 골라도102개 중53개는 공개 참조와IoU>0.5에 도달할 수 없다. 이는 기하학적 참조 상한이며 실제 test PQ 상한은 아니다.
- 같은 객체 수라도 GT와의IoU가0.5 기준을 넘으면 FP·FN이 TP로 바뀌어 RQ가 개선될 수 있다.0.03 상승을 SQ만의 개선으로 단정하지 않는다.
- 고정102개 참조는 `configs/reference102.json`에 저장했다. 고정216개는 누락 후보 회수,102개는 부분 검출의 형상·범위 차이를 조사하는 보조 대상으로 사용한다. 어느 쪽도 개별 정답 라벨로 간주하지 않는다.
- 최신 T4 baseline과R1은216개 중2개,102개 중1개와IoU>0.5로 대응한다. R1이 두 참조 집합에서 새로 복구한 대응은0개다.
- 다음 자체 모델 실험은 **이미 존재하는 더 나은 원시 후보를 선택하는 방법**, **불필요한 부분을 줄이거나 충분한 범위를 복원하는 방법**, **원시 후보 자체가 없는 객체를 찾는 방법**을 나누어 검증한다. 과거 실행의 최종CSV만으로 원시 후보 존재 여부를 단정하지 않는다.

## 1순위: 후보 생성과 선택을 분리해서 진단

각 공개 마스크를 다음 순서로 비교한다.

1. YOLO의 원래 4개 기하학 뷰, 전처리 8뷰, 타일 18뷰의 개별 후보.
2. Native base/TTA의 저장된 임계값별 개별 연결요소. Native union의 위치 지지도는 별도로 기록한다.
3. 기존 후처리 단계별 출력: consensus → preprocessing rescue → smooth → tiled → native reference → rich refined → final.
4. 같은 실행에서 저장된 최종 baseline과 R1 출력.

- **개별 원시 후보에 IoU > 0.5 대응이 있고 최종에는 없음:** 그 후보의 유지·선택·형상 변경 과정을 먼저 조사한다. 초기 confidence 제한, 다중 뷰 지지도, 중복 제거, native pruning을 하나씩 검증한다. 단계 간 대응 소실은 관찰이며 세부 원인은 해당 단계의 조건을 확인해야 한다.
- **후보들에 부분적 위치 지지는 있으나 개별 대응이 없음:** 분리·병합 또는 경계 형상 문제를 조사한다. 여러 조각의 union이 겹치는 것을 개별 객체 검출 성공으로 세지 않는다.
- **저장된 원시 후보에도 대응이 없음:** 검출 해상도, 전처리, 타일 위치, 검출기 학습을 우선한다. 저장되지 않은 임계값 이전 예측의 존재 여부까지 단정하지 않는다.
- **후보와 최종 모두 대응:** 경계 보정의 득실을 분석한다. R1 전후의 참조 IoU 변화와 실제 validation PQ 변화는 별도로 기록한다.

캐시는 신원·원본 이미지 SHA·GPU 실행 기록·상위 단계 해시를 확인한다. 후처리를 CPU로 재현한 최종 마스크는 저장된 baseline과 일치해야 한다. 캐시가 덜 저장된 상태를 '후보가 없음'으로 처리하지 않는다.

## 진단 이후의 실험

### 후보 복구

- 공개와 달랐던 사례에서 반복적으로 나타난 탈락 조건을 찾는다.
- 공개 마스크 없이도 계산할 수 있는 confidence, 서로 다른 뷰의 지지도, native 지지도, 이웃 객체와의 충돌 정도로 복구 규칙을 만든다.
- 초기에는 한 가지 탈락 조건만 완화한다. 원래 후보를 모두 더하는 방식은 사용하지 않는다.
- 5-fold OOF에서 기존 참조 `C4_then_C2_then_R1_once`와 비교하며 PQ·TP·FP·FN과 fold별 결과를 기록한다. 반복 사용한 OOF는 개발 데이터임을 유지한다.

### 분리·병합과 경계

- 참조와의 대응 관계를 이용해 꼬리 손실, 과도한 분리, 잘못된 병합의 사례 목록을 만든다.
- 실제 이미지에서 어두운 연결부, 끊어진 간격, 다른 뷰의 일관성을 사용해 조건부 규칙을 제안한다.
- 현재 실행 중인 R1 결과를 먼저 확인하고, 효과가 있던 사례와 없던 사례를 구분한다. 동일 마스크에 R1을 반복 적용하지 않는다.

### 학습으로 이어지는 활용

- 참조 불일치 영역의 길이·폭·태양 원반 내 위치를 조사한다. 대비·밝기는 원본 이미지가 있을 때만 측정한다.
- 그 특성에 대응하는 **정답이 있는 train 사례**를 더 자주 학습하거나, train 유래 합성 마스크의 분포를 조절한다.
- 선택기나 모델을 다시 학습할 때는 기존 고정 train/validation 분할을 사용한다. 공개 test 예측을 정답으로 간주해 기존 validation에 섞지 않는다.
- test 의사라벨 학습은 대회 규정·원본 이미지·독립 평가 방식을 확인한 뒤 별도 실험으로 다룬다. 이번 진단 도구는 학습을 하지 않는다.

## 결과 해석과 다음 판단

- 우선 목표는 225개를 무조건 추가하는 것이 아니라, 우리 출력에 대응이 없었던 참조 마스크가 **후보 생성 / 선택 / 형상 변경 중 어느 부분과 관련되는지** 수치로 분류하는 것이다.
- 개별 참조와의 IoU > 0.5 비율은 '참조 후보 포괄률'이다. 숨겨진 test 정답 recall이나 PQ가 아니다.
- 자체 pipeline에서 참조 없이 작동하는 수정안을 검증한 뒤 소수의 고정 후보를 leaderboard에서 확인한다. 0.55 자체 CSV를 수정하는 제출은 별도 실험 번호로 기록한다.
- 현재 서버에는 실행 중인 Colab Drive의 test 원시 캐시가 없다. 캐시 추적의 실제 수치는 Colab 추론 완료 후 진단 ZIP을 받아 계산한다. 클라우드에서는 보유한 과거 두 제출의 비교와 진단 코드 검증을 할 수 있다.
