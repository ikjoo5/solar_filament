# DETR–best84 T4 결과 검토

- 검토일:2026-11-02. 업로드:`detr_best84_d594c020e79f_part01.zip`.
- 결론: **실행과 점수 계산은 정상이다. 이번 DETR 타일 선택 방식의 실질적인 개선은 확인되지 않았다.** FN·FP를 줄인 결과가 아니며, 추가 제출 후보로 우선 채택할 근거가 약하다.
- 같은 실행에서 재계산한 기준선 PQ0.472274에 비해 최고 후보는0.472556, 차이는+0.000282다. TP488·FP205·FN220은 동일하다.
- 현재 공개 예측 제출의 확인된 public LB0.55, 자체 파이프라인의 기존 public LB0.39, 본 개발 validation 점수는 각각 다른 평가다. 본 결과로 어느 LB 점수도 갱신하지 않는다. 사각형2개 제거 제출도 사용자가 public LB0.55로 동일함을 확인했다.

## 1. 정상 실행 여부

- ZIP은1/1개로 완전하며 CRC검사를 통과했다.208개 파일 크기·SHA가 export manifest와 일치한다.
- 코드12개와 prediction seed는 최초 배포 패키지와 바이트 단위로 동일하다.
- 원본 annotation/train/validation 분할 해시 및91사진의 입력 해시가 일치한다.182개 단계 기록(native91+ROI91)의 내부 payload SHA와 identity도 일치한다.
- 실행은 Tesla T4, FP16, batch1이다. 추가 학습은0epoch이며 기존 DETR70/80 bbox를 재사용했다.
- torch2.11.0+cu130, CUDA13.0, cuDNN92700, cuDNN v8 비활성화 설정이 기록되어 있다.
- 가중치·원본 영상이 업로드 ZIP에 포함되지는 않아 GPU forward를 여기서 다시 돌린 것은 아니다. 저장된 예측 CSV를 원래 GT로 독립 재평가했다.

## 3. 최고 후보의 작은 상승은 어디서 나왔는가?

native3개 설정 모두 같은 정답1개를 새로 찾고 같은 정답1개를 잃었다.

|변화|GT|면적|기존 최종 최대 IoU|타일 선택 후 최대 IoU|
|---|---|---:|---:|---:|
|복구|060102-20190322144450Bh_2|445px|0|0.758491|
|손실|020401-20171007133710Th_1|565px|0.564103|0|

- 최고 arm의 matched-IoU 합 증가0.19758095 중0.19438800(약98.4%)은 이 두 정답의 교체에서 나왔다.
- 공통으로 맞춘487개 정답에서 IoU 합 증가는0.00319295, 평균 증가는0.00000656에 불과하다. 전반적인 경계 개선으로 해석할 수 없다.
- FP도 새1개와 삭제1개가 상쇄됐다. FN과 작은 객체 recall은 그대로다.

후보 추가 단계의 평균 foreground 확률≥0.9 조건을 추적하면 원인이 더 분명하다.

- 복구된 객체는 full의 raw 후보에도 이미 있었다(IoU0.757116). 평균 확률0.882821로 탈락했으며, 선택 타일에서는0.923144로 올라 통과했다. 마스크 면적은481→487px로 거의 같다.
- 잃은 객체의 raw 마스크는 모든 설정에서 동일했다(IoU0.564103,면적594px). 평균 확률이0.901733→0.891928로 바뀌며 같은0.9 문턱에서 탈락했다.
- 따라서 주요 차이는 새 객체 검출이나 경계 개선보다 **기존 후보가 확률 문턱을 넘거나 못 넘은 변화**다. 이것만으로 문턱을 낮추는 규칙을 채택하지는 않는다.

## 4. 이번 실험이 실제로 바꾼 범위

- best84 입력은 기존 원해상도1024타일이다. DETR bbox를 중심으로 새 crop을 만들거나 대상을 확대하지 않았다.
- 기존 타일 중 DETR bbox를 덮는 타일을 선택해 확률을 합성하고, 선택 영역 밖은 같은 뷰의 full-native 확률로 보완했다.
- 실제로는 모든 사진의 전체36타일 forward를 계산하고4개 native arm이 공유했다. 총3,276회이며 선택 타일 수만큼 연산을 절약한 실험이 아니다.

|설정|선택 타일 평균/36|4뷰 합집합 커버리지|최종 union 변경 픽셀/91사진|
|---|---:|---:|---:|
|DETR70 c0.8|19.09|84.24%|3,055|
|DETR80 c0.6|21.70|88.03%|2,500|
|DETR80 c0.8|19.59|85.44%|3,187|

- 변경 픽셀은 사진당 평균 약27~35개다. foreground0.5 TTA 영역의 변경도 기준선 foreground 면적의약0.29~0.48%였다.
- 이처럼 입력 내용과 최종 마스크가 대부분 유지됐으므로 이번 결과는 제한된 타일 합성 변경에 대한 결과다. **DETR bbox를 실제 ROI로 활용하는 모든 접근이 실패했다는 뜻은 아니다.**
- 별도 ROI arm은 실제 bbox context1.5 crop을384로 변환해 고정 ResNet34 ROI U-Net30에 입력했다.

## 5. raw 후보와 ROI의 보완 가능성

- 이번에 내보낸 native base/TTA의 threshold0.2/0.35/0.5/0.65/0.8 연결요소 후보를 합쳐도, IoU>0.5 후보가 있는 GT 수는 full529/708,DETR70 528,DETR80c0.6 529,DETR80c0.8 528이다.
- 타일 선택으로 새롭게 후보가 생긴 GT는0개였다. 이 범위는 해당 native 후보만이며, 과거 다른 실험의 YOLO·추론 뷰 전체 후보 포괄률과 직접 비교하지 않는다.
- ROI는 기준선이 놓친 일부 정답을 찾지만, 전체를 교체하면 손실이 더 크다.

|ROI 설정|기준선 대비 새로 찾은 GT|잃은 GT|FP 증가|
|---|---:|---:|---:|
|70 c0.8|41|80|+136|
|80 c0.6|48|68|+339|
|80 c0.8|38|76|+157|

- ROI3개 결과의 정답 매칭을 모두 합치면 기준선 FN 중57개에서 보완 가능성이 관찰된다. 이는 정답을 보고 집계한 진단 상한이며 실제 선택기로 복구했다는 성능이 아니다.
- 기존 마스크와 maxIoU<0.1인 ROI 후보만 남기는 단순한 추가 조건도 정답/오탐 선별력이 부족했다. ROI70은 추가 후보에서GT14개와FP105개,ROI80c0.6은GT26개와FP272개,ROI80c0.8은GT17개와FP127개가 관찰됐다. 이 수치는 각 후보 집합의 진단이며 완성된 합성 제출의 PQ가 아니다.
- 따라서 ROI 결과를 그대로 더하거나 기존 파이프라인을 통째로 교체하는 방법은 권하지 않는다. 후보 신뢰도·일관성·이미지 근거를 이용한 선택을 실제 GT로 검증해야 한다.

## 6. 불확실성과 판단

91개 물리적 사진을 묶어5,000회 paired bootstrap을 독립 재현했다.

|설정|기준선 대비 ΔPQ|95% 구간|
|---|---:|---|
|DETR70 c0.8|+0.000282|[−0.001589,+0.002429]|
|DETR80 c0.6|−0.000116|[−0.001885,+0.001975]|
|DETR80 c0.8|+0.000239|[−0.001630,+0.002403]|

- 모든 구간이0을 포함한다. 반복 사용한 개발 데이터에 대한 기술적 구간이며 모델/설정 선택에 대한 보정은 없다.
- `result.json`의 `submission_candidate`는 세 설정 중 관측 PQ가 가장 큰 항목을 자동 기록한 것이다. 유의미한 개선이나 리더보드 상승을 보장하는 표시가 아니다.
- **이번 타일 선택 방식은 채택 보류**가 타당하다. 같은 미세 변경을 추가 반복하거나 이 결과만으로 학습 에폭을 늘릴 근거는 부족하다.
- 다음 bbox 실험이 필요하면 실제로 bbox 중심의 입력·스케일을 바꾸는 crop 조건을 따로 정의해야 한다. 기존 best84의 학습 스케일과의 적합성을 먼저 확인하고, bbox 정확도·segmentation 품질·후보 선택을 분리해 평가한다.
- 현재 확인된0.55 제출을 개선하는 RLE 비교 연구는 별도로 이어갈 수 있다. 본 validation 결과를0.55 test 예측과 직접 합치거나 validation용 DETR seed를 test에 재사용하면 안 된다.
