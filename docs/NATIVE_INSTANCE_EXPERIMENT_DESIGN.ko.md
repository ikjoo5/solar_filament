# 새 U-Net 구조 비교 실험 설계

기존 YOLO+native 제출 구성을 강제하지 않고, 실제 대회 train만으로 새로운 U-Net을 학습한다. 이 문서는 새 실험의 설정과 해석 범위를 기록한다. 아직 새 모델의 대회 PQ·T4 학습 시간·최대 메모리를 측정한 결과가 아니다.

## 첫 실행 범위와 비교

- 기본 실행은 **ResNet34 U-Net 한 모델, 실제 최종 목표 30에폭**이다. 세 모델이나 5-fold를 자동으로 연속 학습하지 않는다.
- ResNet18, ResNet34, ConvNeXt-tiny encoder와 `semantic` / `instance` 학습 방식을 선택할 수 있다. 설정을 바꾸는 비교는 각각 별도 결과 폴더를 사용한다.
- 새 모델은 ImageNet encoder 사전학습에서 시작한다. 구조가 다른 기존 native best84 가중치를 새 ResNet 모델의 학습 가중치로 재사용하지 않는다.
- 같은 새 모델의 전경 확률에 연결요소 디코딩과 인스턴스 분리 디코딩을 모두 적용해 비교한다. 이는 같은 모델에서 디코딩의 영향을 비교하는 것이며, 전경만 학습한 별도 모델과의 학습 손실 ablation을 대신하지 않는다.
- 기존 YOLO+native PQ 약 0.472와 기존 native 단독 PQ 약 0.43은 참고 기준이다. 새 구조가 이보다 높아질지는 실제 학습 후 검증한다.

## 데이터와 학습 예산

- 기존 고정 **train 616장 / validation 91장**을 유지한다. 같은 사진의 주석자는 모두 같은 분할에 남긴다.
- 주석자별 train 레코드 1,053개는 대안 주석 그룹으로 따로 사용한다. 다른 주석자의 정답을 임의로 하나의 instance 집합으로 합치지 않는다.
- 첫 실험은 **실제 train만 사용**한다. 앞선 합성 v2/v3 결과와 공통 추가 학습 설정의 영향을 혼동하지 않기 위한 기준점이다.
- 기본 crop 768, batch 2, gradient accumulation 2, 에폭당 mini-batch 256개를 사용한다.
- 여기서 1에폭은 **무작위 crop 512개의 고정 샘플링 예산**이다. 원사진 616장이나 주석 레코드 1,053개 전체를 정확히 한 번씩 도는 뜻은 아니다.
- 30에폭은 crop 15,360개, optimizer update 시도 최대 3,840회에 해당한다. AMP가 update를 생략한 경우 실제 수는 달라질 수 있다.
- train GT 안의 점을 포함하는 crop을 약 70% 제안하고, 나머지는 무작위 crop으로 음성 배경도 학습한다. crop 일부에 걸친 객체의 라벨도 유지한다.
- 영상과 instance-ID 마스크에 같은 90도 회전·반전을 적용한다. 밝기·gamma 증강은 영상에만 적용한다.

## 출력과 정답

네트워크는 세 개의 출력을 가진다.

1. **Foreground**: 필라멘트 전경 전체. 경계 학습 때문에 전경 정답을 깎지 않는다.
2. **Boundary**: 전경 바깥 윤곽과 서로 다른 instance가 접하는 경계. 객체끼리 직접 닿는 픽셀만 경계 정답으로 쓰면 대부분의 실제 객체에 양성 신호가 없을 수 있어, 외곽선도 포함한다.
3. **Per-instance distance**: 각 객체 안의 경계까지 거리이며 객체마다 정규화한다. 전경 내부의 distance loss만 적용한다.

`semantic` 방식은 foreground 손실만 학습한다. `instance` 방식은 foreground 손실에 boundary·distance 손실을 더한다. 한 픽셀 폭의 필라멘트가 경계 정답 전체와 겹치더라도 foreground 정답은 유지한다.

최종 손실은 foreground BCE+Dice에 `0.25 × (boundary weighted BCE+Dice)`와 `0.25 × foreground 내부 distance SmoothL1`을 더한다. 경계의 양성 비율이 작아 경계 BCE만으로 학습하지 않도록 Dice 항도 포함한다. 이 계수는 이번 실험의 고정 설정이며 validation 점수로 탐색해 고른 값이 아니다.

인스턴스 분리 디코더는 boundary와 distance로 객체 내부의 seed를 만들되, 하나의 길고 휘어진 필라멘트에 생기는 많은 local maximum을 그대로 별도 객체로 만들지 않도록 제한한다. 안정적인 seed가 없거나 얇은 객체 전체가 경계인 경우 연결요소를 보존하는 fallback을 둔다. 이 설계가 합침·쪼개짐을 모두 해결한다고 가정하지 않는다.

실제 train GT 7,491개의 근접 쌍을 확인했을 때, 8방향으로 직접 닿거나 겹치는 쌍은 9개(관련 GT 18개, 주석 그룹 9개)였다. 따라서 직접 맞닿는 instance의 접촉선만 학습하는 boundary는 양성 신호가 지나치게 드물다. 64개 결정론적 train crop에서 외곽선·접촉선을 포함한 boundary 비율도 평균 약 0.197%로 작았다. 이는 경계 손실에 클래스 불균형을 고려할 근거이며, 특정 손실이 실제 대회 점수를 올렸다는 결과는 아니다.

분할 후 조각 하나라도 지정한 최소 면적보다 작아지는 경우에는 원래 전경 연결요소로 되돌린다. 예를 들어 400px 객체가 200px 두 조각으로 갈라졌을 때, 최소 면적 300 조건에서 두 조각을 모두 버려 기존 객체까지 잃지 않도록 한다.

## 평가와 중단 후 복원

- 학습에 validation 영상·마스크·주석을 넣지 않는다. validation은 지정한 완료 에폭의 공식 strict IoU >0.5 PQ·FP·FN 평가에 사용한다.
- 같은 2048×2048 원본에서 crop을 겹쳐 추론한 뒤 원래 좌표의 확률 지도로 합친다. 두 디코더는 같은 확률 지도를 사용한다.
- 최소 면적 300을 기본 비교로 두고 150도 개발 진단으로 함께 기록한다. 분리 디코딩은 최소 면적에 따라 fallback이 달라질 수 있으므로 각 면적 조건을 별도로 계산한다. `semantic` 학습에서는 훈련하지 않은 auxiliary 출력을 사용하는 분리 디코더를 평가하지 않는다.
- 모델·optimizer·scheduler·AMP scaler·난수 상태와 완료 에폭을 Drive에 함께 저장한다. 중단된 에폭의 일부 batch는 다시 실행한다.
- 기본 `RUN_UNTIL=30`과 전체 스케줄의 최종 목표가 모두 30이다. 중간 점검을 위해 10·20에서 멈추더라도 최종 목표 30은 유지한다.
- 모델·소스·데이터·설정의 identity를 확인하고, 다른 설정을 기존 checkpoint에 섞어 재개하지 않는다.
- 코드·설정·가중치는 Drive에, 다시 만들 수 있는 임시 영상·확률 캐시는 `/content`에 둔다. 런타임 초기화 후 Drive의 저장 코드로 복원한다.

## 해석 제한

- 이번 고정 validation은 여러 번 사용한 개발 세트다. 점수 상승을 새 LB 성능이나 독립 5-fold 결과로 표현하지 않는다.
- 현재 저장된 U-Net 예측의 일부 합침 사례는 새 instance 출력의 근거이지만, 미검출 전체가 인스턴스 합침 때문에 생긴 것은 아니다. 전경 recall과 작은 객체 recall도 함께 본다.
- CPU fixture의 학습·재개·마스크 분리 검증은 코드의 동작 검사다. 실제 T4 메모리, 학습 시간, 새 모델 PQ를 보장하지 않는다.
- 다른 encoder나 손실의 우열은 같은 데이터·crop 예산·평가 조건에서 비교해야 한다. 한 모델의 연결요소/분리 디코딩 비교만으로 encoder 또는 auxiliary loss의 효과를 분리했다고 주장하지 않는다.
